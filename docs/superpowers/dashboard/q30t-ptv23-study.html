Key insights and mistakes

Consolidated. Each is a lesson that changed how the study is built, not a log entry.
  1. A validator that cannot fail is the most expensive defect class in this study. It has happened five separate ways: an all-zero assistant mask that transformers warns about instead of raising; a row counter that returned a silent zero on the two largest repos; a checkpoint guard shipped failing open with a test that could not tell; a stager status file calling a repo staged with 5,901 bytes on disk; a completeness check that marked all ten repos INCOMPLETE. Every one produced a number that looked right. The rule that came out of it: a check has to be shown failing on a case it is meant to catch, not merely shown passing.
  2. Code the tests reach is not the same as code the program reaches. The study’s entire selection design — domain quotas, SWE replay lanes, language policy — was dead. main() called a different selector that raised KeyError: 'arms' on the study policy. Every existing test called the intended selector directly, which is exactly why none of them noticed. Reachability is now checked with an end-to-end CLI test, not a unit test.
  3. A repository can be sorted by the very property you are sampling for. Then .take(n) on a streaming dataset is a lexicographic prefix, not a sample. SFT-Math-v4 is sorted by whether a row has tools. This was a known upstream bug, and it was also sitting in the writer written to replace it. Selection now permutes before taking.
  4. A field that is absent and a field that is empty must not read the same. The PTv2 parquet has no language column at all — language is carried only by the shard filename. Reading it with .get() would make a normalizer that forgot the field look like a corpus with nothing to deny, admitting every denied-language row silently. The language is now required, and its absence raises.
  5. A fix that is committed is not a fix that is deployed. Cluster profiles pinned a commit that predated the fix they depended on. A job submitted against it would have run to completion and written nothing. Pins now name a checkout that is verified to exist at that sha.
  6. Measure the scheduler instead of reasoning about it. sbatch --test-only is free, never enters the queue, and overturned the plan outright. It also settled the partition question: chained batch beats one long batch_long job, which additionally needs approval. Two throwaway 1-minute jobs named a blockage that Slurm had reported for half an hour as Reason=None.
  7. The serving path and the training path fail in different places, and only one of them is loud. There is no method: "dflash2" in vLLM — DFlash2 is served as "dflash", so a wrong drafter yields a plausible number rather than an error. The eval harness was also passing block size where vLLM wants draft length, which would have made the three arms incomparable. The three arms do not share a draft length.
  8. A wrong EAGLE_CAPTURE_IDS final layer id silently caps acceptance length. No crash, no warning — just a worse drafter. This is why the aux-layer-id convention is being settled before export rather than after the first disappointing number.
  9. Hardware assumptions are per-node, not per-cluster. Lyris’s login node is x86_64 while its compute nodes are aarch64 Grace. GB300 is invisible to the scheduler on every attribute except the node name. The GPU nodes are the wide CPU hosts and the data movers are the narrow ones. DFlash attention was running an Ampere sm80 kernel on Blackwell at roughly 2.5 % of peak.
  10. On shared clusters, inodes bind before capacity, and an unbounded search is an outage. An unbounded find /lustre ran 50 minutes from the Lyris login node — the exact practice the MARS conduct doc names. du -sh on Lustre under-reports a directory still being written and nearly triggered a false corruption alarm. Every listing is now scoped to one named directory, with 60 s between checks.
  11. Secrets leak through argv and through file modes, not just through commits. The staging script put a live Hugging Face token in curl’s argv on five shared login nodes, under a header claiming it was safe. On OCI-HSG the tokens were world-readable the moment they were set (home 755, .bashrc 644). Tokens now go over stdin, and are compared by sha256 fingerprint rather than printed.
  12. Check upstream before writing the patch, and read what a source actually says. A staging tool with sha256 verification already existed in the repo; a shell script was written instead. A delegated research result sent the study to a prunable nightly when a stable release already had the feature. rows = 0 from the datasets-server means unconverted, not empty — the four repos it called empty hold millions of rows. git log -- <file> is not the file’s history, and reading it as such reopened a settled question.
  13. An index into the list you built is not an index into the manifest you wrote. write_manifest canonicalizes experiment order, so the submitter’s --experiment-index addressed different arms than the ones enumerated at build time. Four arms were submitted believing they were DFlash2; they were DFlash and DSpark. Nothing was corrupted — every arm belonged in the matrix — but the intended method went unqueued, and a silent method swap is exactly the failure this study cannot detect from its own metrics. Selection now reads the stored order back out of the written file.
  14. The image is not where DFlash2 comes from at this pin. Upstream vLLM ships qwen3_dflash2.py only from 0.28.0. The study pins the 0.27.1 image and gets DFlash2 from the compiled PR-52816 runtime archive that overlays it at run time. So re-staging 0.27.1 from the registry on a second cluster fails the staging script’s own draft-architecture check — that check silently encodes the 0.28.0 assumption. The pinned image had to be copied cluster-to-cluster rather than rebuilt, which is the better outcome anyway: both clusters now run the identical e7be53f2 squashfs, so a method comparison cannot be confounded by the environment.
