Key insights and mistakes

  1. A repository can be sorted by the very property you are sampling for, and then a prefix take is not a sample at all. SFT-Math-v4 looked heterogeneous across shards, so I asked for the remaining nine footers expecting a scatter. It is not a scatter: shards 00000–00006 carry zero tool-bearing rows, 00007 is 49.3 %, and 00008–00011 are 100 %. The file is sorted on the attribute. Combined with the prefix take, that turns a sampling question into a threshold: any cut at or before cumulative row 264,625 of this repo yields no tool-bearing rows whatsoever, so the string-typed function.parameters hazard cannot appear in a small canary and appears abruptly once the blend reads past 48.5 % of the repo. A canary that reads a prefix does not sample the corpus, it samples the corpus’s sort order — and a defect that lives in the tail is invisible to it by construction. The same reasoning says the second, larger cut nobody recorded matters too: multilingual_de ships 38 shards and only 10 were materialized, so the family was truncated once before the take ever ran.
  2. I shipped a guard yesterday that could not fire, and the test I wrote could not tell. The DFlash2 incomplete-checkpoint guard intersected bare parameter names against missing_keys. My test called load_state_dict on the DFlash2 module directly, where the keys are bare, so it passed. Real resumes load the parent model, where the same keys arrive as dflash_module.layers.0.attention_conv.… and match nothing — a checkpoint missing every DFlash2 weight would have loaded silently, which is precisely the failure the guard exists to prevent. It failed open, and it failed open in exactly the direction that produces a plausible training curve on a randomly-initialized drafter.
