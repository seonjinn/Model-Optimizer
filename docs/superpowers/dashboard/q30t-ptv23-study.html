Key results

No training runs launched yet. Acceptance length τ, block size B, and end-to-end rollout throughput at both high and low concurrency land here as milestones report.

Key insights and mistakes

  1. A permission denial on one subdirectory is not evidence about the tree. Tested only <project>/users on AWS-CMH-03 and OCI-AGA, found it root-owned, and wrote a spec section declaring the study GB200-only. The project root itself is group-writable on both. Walk up one level before concluding. Cost: one wrong spec section and a discarded hardware plan.
  2. A bounded search proves nothing about what lies outside its bound. A find -maxdepth 4 scoped to my own directory could not reach a depth-6 path under another user's, and the absence of hits was reported as "no staged corpus exists anywhere." It existed, 42 G of it. State the scope of a negative result alongside the result.
  3. Unbounded find on shared Lustre from a login node is prohibited, and I ran one. MARS records an unbounded scan that ran 20–29 hours and degraded the filesystem for everyone. Scope every scan to your own directory; never leave one running.
  4. A revoked token and a gating denial look nothing alike — check whoami, not the artifact. Lyris and Ptyche appeared to lack a token. They had one; it was fully revoked (401 on whoami, not just on the gated dataset). Fingerprint tokens with sha256 and test the identity endpoint before assuming an environment problem.
  5. DFlash attention was running an Ampere sm80 kernel on Blackwell at roughly 2.5 % of peak. A materialized [B,1,Q,KV] additive mask disqualifies every fused backend, so PyTorch silently fell through to the cutlass memory-efficient path, whose only kernel is sm80. That single backward kernel was 59 % of the step. Silent backend fallback is the most expensive kind of correct-but-slow.
  6. A wrong EAGLE_CAPTURE_IDS final layer id silently caps acceptance length. Capturing the second-to-last hidden instead of the true final one trains without error and just produces a worse drafter. There is no failure signal, so the id has to be derived (build_target_layer_ids(n_layers, n_draft) + 1, plus the true final) rather than guessed.
  7. Trainer memory is set by the loss tensor, not by sequence length. [N, vocab] with N = per_device_batch × num_anchors × block_size dominates, and is independent of training_seq_len. All three arms are held at num_anchors × block_size = 4096 so memory is comparable across them.
  8. The three arms do not share a draft length. DFlash and DFlash2 give K = B − 1; DSpark gives K = B, because its shift-label alignment does not exclude position 0. Comparing arms at equal B but reporting a single K would misattribute the difference. NUM_SPEC_TOKENS is an independent serving knob bounded above by K.
  9. Inodes, not capacity, are the binding storage constraint. Every cluster has hundreds of terabytes free; Lyris is at 93.4 % of its soft inode limit. Checkpoint and shard layout has to favour few large files over many small ones, and the quota that matters is the one nobody checks.
  10. Idle GPUs can get the job killed by the scheduler. In the producer-consumer topology (vLLM serve nodes plus DDP trainer nodes), a stalled serve leaves trainer GPUs idle and risks auto-termination of a 16-node job. Node counts must be sized so both halves stay busy.
  11. DFlash2 is served as method: "dflash", so a wrong drafter produces a plausible number instead of an error. vLLM picks the V2 speculator from the draft checkpoint's architectures (DFlash2DraftModel), not from the method string (vllm#52816). A DFLASH2 run pointed at a DFlash checkpoint starts cleanly, benchmarks DFlash, and reports it as DFlash2. Only a pre-flight check on the checkpoint can catch it — hence _assert_draft_architecture.
  12. Check upstream before writing the patch, not after. Wrote and committed a DSPARK branch for specdec_bench, then found PR #2027 had already merged a better one two days earlier (num_speculative_tokens default 7, plus draft_sample_method). Reset the commit and cherry-picked #2027 instead. A one-minute gh pr list would have saved the whole detour.
  13. A cluster QOS can enforce a minimum allocation, not just a maximum. A 1-GPU probe on OCI-AGA was rejected with QOSMinGRES; 4 GPUs is the floor. Node generation is also invisible from the scheduler — Gres=gpu:4, RealMemory=942080, and the feature list are identical on GB200 and GB300, so HBM can only be read from inside a GPU job.
